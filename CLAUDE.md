# antoninolattene-child — CLAUDE.md

WordPress child theme for Antonino Lattene's personal portfolio. Built with Vite + SCSS + GSAP.

---

## Stack

| Layer | Tool |
|-------|------|
| CMS | WordPress (child theme) |
| Bundler | Vite 5.3 |
| Styling | SCSS + CSS custom properties |
| Animation | GSAP 3.12 + ScrollTrigger |
| Carousel | Swiper 11 |
| Icons | Font Awesome 7, Material Symbols Rounded |
| Font | Inter (Google Fonts) |
| Local server | MAMP (localhost/antoninolattene) |

---

## Dev workflow

```bash
npm run dev       # Start Vite dev server on :3000 + create "hot" flag file
npm run build     # Production build to dist/ + remove "hot" flag
npm run cache-clear  # Clear Vite's internal cache (node_modules/.vite)
```

**How dev mode works:** `npm run dev` creates a `hot` file at theme root. PHP (`functions.php`) detects this file via `is_vite_dev_mode()` to serve assets from `http://localhost:3000` instead of `dist/`. Always run `npm run dev` when editing JS or SCSS.

**Proxy:** Vite proxies non-asset requests to `http://localhost/antoninolattene` (the MAMP WordPress instance). Access the site at `http://localhost:3000` during development.

## Key PHP patterns

### Asset enqueuing (Vite integration)

`functions.php` has a dev/prod switching system — never hardcode asset URLs:

```php
// Check if dev server is running
is_vite_dev_mode()  // returns true when "hot" file exists

// Resolve a source asset to the correct URL
get_vite_asset('js/gsap.js')         // dev → localhost:3000/src/js/gsap.js
get_vite_asset('styles/style.scss')  // prod → dist/assets/main-[hash].css
```

The manifest at `dist/.vite/manifest.json` is parsed in production to get hashed filenames.

### Page templates in subdirectories

The function `antoninolattene_child_add_nested_page_templates()` in `functions.php` allows page templates to live in subdirectories like `page-templates/page-about/page-about.php`. Register new templates this way.

### Custom meta boxes (posts & portfolio)

- **Featured Video URL** — alternative to featured image for video content
- **Client Name** + **Chip Color** — displayed as colored chip on project cards (22 color presets)

### Theme Customizer options

- **Availability status** — available / limited / not-available
- **Alternative logo** — for scroll animation
- **Portfolio archive** — title and description
- **Resume link** — URL to CV

### Breadcrumbs

`antoninolattene_breadcrumbs($mode)` in `functions.php`. The `$mode` parameter accepts `'full'` or `'category_only'`. Icons are mapped from category slug in `get_category_icon_map()`.

### Shortcodes

- `[banner title="" text="" ...]` — customizable inline banner
- `[credit name="" link=""]` — photography credit

## JavaScript architecture

All modules are initialized in `src/index.js` inside `DOMContentLoaded`. Swiper instances are guarded by a DOM check before init:

```js
if (document.querySelector('.testimonials-swiper')) initTestimonialSwiper();
```

**Adding a new JS module:**
1. Create `src/js/your-module.js` and export an `init` function
2. Import and call it in `src/index.js`

## GSAP animation conventions

Constants defined at top of `gsap.js` — change these to tune all animations globally:

```js
const ANIM_DURATION = 0.4;
const ANIM_EASE = "power1.out";
const FADE_IN_DISTANCE = 50;
const STAGGER_TIME = 0.3;
const SCROLL_TRIGGER_START = "top 92%";
```

Scroll-triggered animations use `ScrollTrigger.batch()` for performance. The pattern is: elements start at `autoAlpha: 0, y: FADE_IN_DISTANCE` and animate to `autoAlpha: 1, y: 0` when scrolled into view. `onLeaveBack` resets them.

**Adding a new scroll animation:**

```js
ScrollTrigger.batch(".your-selector", {
    start: SCROLL_TRIGGER_START,
    onEnter: batch => gsap.to(batch, { autoAlpha: 1, y: 0, stagger: STAGGER_TIME, duration: ANIM_DURATION, ease: ANIM_EASE }),
    onLeaveBack: batch => gsap.set(batch, { autoAlpha: 0, y: FADE_IN_DISTANCE }),
});
```

Elements that should animate in must start with CSS `opacity: 0` (or GSAP will set `autoAlpha: 0` via `gsap.set()`).

## Modal system

**PHP markup** (`template-parts/components/modal.php`):

```php
<div class="modal" id="my-modal" aria-hidden="true">
    <div class="modal__overlay" data-modal-close></div>
    <div class="modal__content-wrapper">
        <div class="modal__header"> ... <button data-modal-close> </div>
        <div class="modal__body"> ... </div>
        <div class="modal__footer"> ... </div>
    </div>
</div>
```

**Trigger** (any element):

```html
<button data-modal-target="my-modal">Open</button>
```

**Behavior:** `initModals()` in `modal.js` handles open/close, ESC key, focus on close button, `body.modal-open` scroll lock, and `aria-hidden` toggling.

## SCSS design system

### Spacing scale (`--size-*`)

```
--size-50: 4px   --size-100: 8px   --size-200: 12px  --size-300: 16px
--size-400: 24px --size-500: 32px  --size-600: 40px  --size-700: 48px
--size-800: 64px --size-900: 96px  --size-1000: 128px
```

### Typography

Fluid sizes using `clamp()`. Classes: `.heading-1` through `.heading-6`, `.body-lg`, `.body-md`, `.body-sm`, `.caption`. Font family: `--ff-primary` (Inter).

### Colors

CSS custom properties prefixed `--color-*`. Light/dark mode handled via `[data-theme]` attribute on `<html>`. Key tokens: `--color-text-primary`, `--color-text-secondary`, `--color-surface-primary`, `--color-surface-secondary`, `--color-border-secondary`, `--color-accent-primary`.

### Chip colors

22 color presets defined in `_chips.scss` and registered as meta box options. Chip modifier classes follow `.chip--[color-name]`.

### Adding a new component

1. Create `src/styles/components/_your-component.scss`
2. Import it in `src/styles/style.scss`
3. Create `template-parts/your-component.php` for the markup

## Gotchas

- **`dist/` is git-ignored.** Always run `npm run build` before deploying. The PHP enqueue system reads from `dist/.vite/manifest.json`.
- **`hot` flag file.** If you see JS/CSS not loading in the browser while MAMP is running, check if `hot` exists without a dev server running. Delete it or run `npm run dev`.
- **Vite uses `usePolling: true`** in vite.config.js because MAMP's file system requires polling for watch to work.
- **No linter/formatter configured.** There is no `.eslintrc`, `.stylelintrc`, or `.prettierrc`. Follow existing code style.
- **GSAP elements need initial CSS opacity: 0** (or use `gsap.set()` before ScrollTrigger) to avoid flash of visible content before animation runs.
- **Menu classes** — `functions.php` has several hooks to manage active states on the nav menu for CPT archive pages. Be careful modifying `body_class` or menu filters.
- **Nested page templates** — The custom loader in `functions.php` scans `page-templates/` subdirectories. New templates must have the `Template Name:` header comment to be detected.
